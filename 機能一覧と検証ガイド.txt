 第3部  LLM と MCP 連携しながら検証する手順

■ 3.0 準備 (1 回だけ)
  1. ビルド:  build.bat  (または  cmake --build build --config Release)
     実行ファイル: build\Release\v-simple-editor.exe
  2. 自動テスト (GUI 不要。exit code 0 = 全ゲート PASS):
       build\Release\v-simple-editor.exe --selftest=mcp
       build\Release\v-simple-editor.exe --selftest=fxgrain-echo
       build\Release\v-simple-editor.exe --selftest=reverse-clip
       build\Release\v-simple-editor.exe --selftest=tcburn
       build\Release\v-simple-editor.exe --selftest=dynzoom
     標準エラー出力に PASS G1 ... / summary: N PASS, 0 FAIL が出ます。
  3. エディタを起動し、検証動画/ の素材を 2〜3 本タイムラインへ置く
     (ファイル > ファイルを開く、または後述の import_media を LLM に頼む)。
  4. 画面右下の「LLM に指示を出す」ボタンを押す
     → MCP サーバが起動し AI チャット Dock が開きます。
     Dock 下部に「MCP: 待受 127.0.0.1:8765」「CLI: Claude Code (検出済み) / モデル名」が出れば OK。
     CLI が未検出なら:  npm i -g @anthropic-ai/claude-code   (Codex なら npm i -g @openai/codex)
  5. 外部ターミナルから使う場合:
       ツール > MCP サーバ > 接続情報...  で mcp.json をコピー → veditor-mcp.json に保存
       claude --mcp-config veditor-mcp.json --strict-mcp-config

■ 3.1 共通の検証ルール
  ・LLM への指示は「〜して」と自然文で OK。LLM が MCP ツールを選んで実行します。
  ・各操作後に次の 3 点を確認:
      (a) タイムライン/プレビューが指示どおり変わった
      (b) Ctrl+Z 1 回で元に戻る (Undo あり のツール)
      (c) get_timeline / get_project_info の応答に新しい値が反映されている
  ・まず「今のタイムラインを教えて」と聞いて get_timeline の出力を見るのが確実です。
  ・ツール ID (list_commands の file.11 等) は位置依存なので、run_command を使う指示は
    「先に list_commands で確認してから」と付けると安全です。
  ・危険なコマンド: 終了系は MCP から実行不可。モーダルダイアログ系は allowBlocking が必要。

■ 3.2 既存機能のスモークテスト (MCP 39 ツール)
  □ 「プロジェクト情報を教えて」                      → get_project_info
  □ 「検証動画フォルダの xxx.mp4 を V1 に取り込んで」  → import_media (V/A ペアで入る)
  □ 「2 番目のクリップを 3 秒の位置で分割して」        → split_clip、Ctrl+Z で戻る
  □ 「最初のクリップを削除してリップルで詰めて」        → delete_clip(ripple)
  □ 「クリップ 1 を V2 に移動して」(V2 が無い場合は LLM が run_command でトラック追加)
  □ 「クリップ 1 の音量を 50%、速度を 2 倍に」          → set_clip_property (音声も同期)
  □ 「クリップ 1 の先頭を 1 秒詰めて」                   → trim_clip(edge=in)
  □ 「クリップ 1 と 2 の間にクロスディゾルブ」          → set_transition
  □ 「0〜3 秒に『テスト』というテロップを中央に」        → add_text_overlay
  □ 「字幕を 2 件追加してタイムラインに適用」            → add_caption ×2 → apply_captions
  □ 「5 秒時点のフレームを見せて」                        → get_frame (PNG が返る)
  □ 「再生ヘッドを 10 秒へ」                              → set_playhead
  □ 「デスクトップに test.veditor で保存」 → 「それを開き直して」 → save_project / open_project
  □ 「mp4 に書き出して進捗を教えて」                      → export_video → get_export_status

■ 3.3 Wave 1 新機能の検証チェックリスト

  ▼ (3) カラーワーパー  (カラーグレーディング パネル > 「カラーワーパー (色相 × 彩度)」)
     手動:  色相環の上の 12 × 3 = 36 個のノードをドラッグ (角度 = 色相シフト -60〜+60°、半径 = 彩度倍率 0〜2)
            期待: そのノード周辺の色相・彩度だけが変わり、隣のノードとの間は滑らかに補間される。
                  ノードをダブルクリックでそのノードだけリセット、右クリック「すべてリセット」で全解除。
                  全ノード既定なら出力は完全に無変化。プレビュー (GPU) と書き出し (CPU) が同じ式。
     LLM:   MCP ツール無し。手動で設定後に get_frame で確認。
     Undo:  Ctrl+Z 1 回で戻る
     selftest: --selftest=color-warper (6 ゲート)

  ▼ (4) 3D カメラの真の透視投影  (コンポジション > カメラモーション... > 「真の透視投影 (回転・注視点・ロールを反映)」)

            期待: レイヤーが台形に見える (OFF ではシア近似で平行四辺形)。カメラの注視点を横に振るとレイヤーが
                  逆方向へ動き、ロールで画面が回る。OFF に戻すと従来と同じ絵。既定 OFF なので旧プロジェクトは不変。
                  fov 欄は従来どおり「焦点距離 (px)」の意味。
     LLM:   MCP ツール無し。get_frame で確認。
     selftest: --selftest=camera3d (9 ゲート)

  ▼ (5) 3D カメラトラッカー  (ツール > プラナートラッカー… > トラッキング後に「3D カメラを解析」)
     手動:  壁や床など平面が写るクリップで 4 隅を置いてトラッキング → 「3D カメラを解析」
            期待: 「有効フレーム: N / M、平均残差: …」のダイアログ → 「はい」でカメラにキーフレームが入り、
                  真の透視投影が ON になる。信頼度 0.5 未満のフレームにはキーフレームが入らず前後から補間。
                  プレビュー・書き出しとも各フレームの時刻のカメラで描画される。
                  Ctrl+Z 1 回で適用前のカメラに戻る (適用後にタイムラインを編集していない場合のみ。1 段分)。
                  平面シーン前提なので、奥行きのある一般シーンでは正しく解けない (Wave 4 候補)。
     LLM:   MCP ツール無し。
     selftest: --selftest=camera-solve (8 ゲート)

  ▼ (6) 受け入れ検証用 render-fixture  (コマンドライン専用)
     手動:  cmd: set VEDITOR_RENDER_FIXTURE_OUT=D:\tmp\fx_new && v-simple-editor.exe --selftest=render-fixture
            期待: (a)〜(f) の fixture (静止画 2 枚、CrossDissolve、速度変更/逆再生/ネスト、グレード、3D レイヤー、音声) の
                  PNG / frames.bin / audio.json が出力され、stderr に HASH 行。旧 exe の出力フォルダと比較して一致。
     selftest: --selftest=render-fixture (3 ゲート)

  ▼ (7) 音声クリップの実オーバーラップ  (音声クリップ右クリック > 音声トランジション > クロスフェード (コンスタントパワー)…)
     手動:  隣接する 2 つの音声クリップ (両方に未使用の頭/尻の余白があるもの) にクロスフェード 1 秒
            期待: 継ぎ目で A の尻と B の頭が実際に 1 秒重なって鳴る (Wave 2 では順番に鳴る「ディップ」だった)。
                  Center at Cut なら A が 0.5 秒伸び B が 0.5 秒早く始まる。余白が足りないと短縮され通知が出る。
                  リンクした映像クリップとの位置ずれは無い。フェードイン/アウトは位置を変えない。
     LLM:   「A1 の 1 番目と 2 番目の間に 1 秒のクロスフェード」→ set_transition (kind:audio)
     呼び出し例:      set_transition {"kind":"audio","trackIndex":0,"clipIndex":0,"type":"CrossDissolve","durationSec":1.0}
     期待レスポンス:  {"ok":true,"kind":"audio",...,"leadIn":{…},"trailOut":{…}}
     selftest: --selftest=audio-xfade (11 ゲート、G9 が継ぎ目の音量ディップ解消)

■ 3.6 Wave 4 新機能の検証チェックリスト

  ※ Wave 4 で MCP に増えたのは compare_project / render_in_place / decompose_render_in_place の 3 ツール (36 → 39)。
     set_transition に alignment / easing / softness / borderWidth / borderColor、get_timeline に leadIn・trailOut の
     詳細と overlap が増えた。mcp selftest は G148..G155 が追加 (G1..G155)。
  ※ 1 件は既存欠陥の修正で結果が変わる: (2) 旧「マルチカメラセットアップ」の音声同期。これまではオフセットを
     推定せず 0 を返していたが、音声の相関で実際に同期するようになった。同ダイアログで作ったプロジェクトは
     オフセットが変わる。基本ダイアログ [ファイル] → [マルチカメラ...] は Wave 2 から実同期なので不変。

  ▼ (1) get_timeline のトランジション詳細と overlap  (MCP のみ)
     LLM:   「タイムラインを読んで」→ get_timeline
     呼び出し例:      get_timeline {}
     期待レスポンス:  clips[].leadIn / trailOut が {"type","durationSec","alignment","easing","softness","borderWidth","borderColor"}、
                      clips[].overlap が {"leadInSec","trailOutSec"} (トランジション無しは 0)。既存フィールドと required は不変。
     selftest: --selftest=mcp G148 (alignment / easing と実オーバーラップ) / G149 (音声オーバーラップと 1 undo)

  ▼ (2) 旧マルチカメラセットアップの実同期 (欠陥修正)  (ツール > マルチカメラセットアップ / 切替)
     手動:  同じ音声を 250ms ずらした 2 素材 + 無音 1 素材を登録して同期
            期待: 「3 本中 2 本を同期しました (音声なし 1 本)」がステータスバーとダイアログに出て、
                  ずらした素材のオフセットが ±10ms で推定される。無音素材はオフセット 0。
     LLM:   MCP ツール無し。
     selftest: --selftest=multicam (G10 が実 WAV デコードで 250ms ±10ms / 無音 / ファイル不在を検証)

  ▼ (3) トランジションのソフトネスと境界線  (挿入 > トランジションを追加 / クリップ右クリック / MCP set_transition)
     手動:  ワイプ / バーンドア / アイリス / クロックワイプのダイアログで「ソフトネス」「境界線の幅」「境界線の色」を設定
            期待: 境界がぼけ、指定色・幅の帯が出る。クロスディゾルブ等では 3 欄がグレーアウト。
                  既定 (0 / 0 / 白) なら従来と byte-identical。プリセット保存で 3 値も残る。プレビューと書き出しが同じ絵。
     LLM:   「クリップ 1 と 2 の間に赤い境界線 6px のワイプ、ソフトネス 0.3」→ set_transition
     呼び出し例:      set_transition {"clipIndex":0,"type":"WipeLeft","durationSec":1.0,"softness":0.3,"borderWidth":6,"borderColor":"#ff0000"}
     期待レスポンス:  {"ok":true,...}。type "CrossDissolve" に softness を付けると {"ok":true,"warning":"この type ではソフトネスは無視されます"}
                      範囲外 (softness 2) はエラー「ソフトネスは0..1、境界線の幅は0..50で指定してください」
     Undo:  Ctrl+Z 1 回で戻る (mcp G150)
     selftest: --selftest=transition-params (10 ゲート。G8..G10 がアイリス / クロック) / --selftest=mcp G150-G151

  ▼ (4) グレードのキーフレーム (HSL セカンダリ / LGG / Log / カラーワーパー)  (カラーグレーディング パネル各セクションの「キーフレーム追加」)
     手動:  再生ヘッド 0 秒で HSL の色相中心を 0、2 秒で 120 にして各時刻で「キーフレーム追加」
            期待: 1 秒で 60 に補間される。プレビュー (GPU uniform) と書き出しが同じ絵。
                  キーフレームの無いクリップは従来と byte-identical。保存 / 再読込で保持。
