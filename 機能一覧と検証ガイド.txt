■ 3.1 共通の検証ルール
  ・LLM への指示は「〜して」と自然文で OK。LLM が MCP ツールを選んで実行します。
  ・各操作後に次の 3 点を確認:
      (a) タイムライン/プレビューが指示どおり変わった
      (b) Ctrl+Z 1 回で元に戻る (Undo あり のツール)
      (c) get_timeline / get_project_info の応答に新しい値が反映されている
  ・まず「今のタイムラインを教えて」と聞いて get_timeline の出力を見るのが確実です。
  ・ツール ID (list_commands の file.11 等) は位置依存なので、run_command を使う指示は
    「先に list_commands で確認してから」と付けると安全です。
  ・危険なコマンド: 終了系は MCP から実行不可。モーダルダイアログ系は allowBlocking が必要。
  ・selftest の読み方 (Wave 8 で追加):
      (a) サマリ行 (標準エラー出力) は `N PASS, M FAIL, K SKIP` の 3 語書式 (GateTally を使う selftest。
          mixer-dock のように `N PASS, M FAIL` の従来書式のものも残っている)。終了コードは FAIL の数なので、
          SKIP があっても FAIL が 0 なら終了コードは 0 になる。終了コードだけで合否を判断しない。
      (b) SKIP は「環境依存で検証できなかったゲート」(エンコーダ無し、Debug ビルドなど) で、未検証を意味する。
          PASS ではない。受け入れ基準がそのゲートを要求しているなら SKIP は未達として扱う。
          VEDITOR_SELFTEST_FORCE_MISSING_ENCODER=<エンコーダ名,...> を付けるとエンコーダ欠如を強制再現できる
          (例: set VEDITOR_SELFTEST_FORCE_MISSING_ENCODER=libvpx-vp9 → build\Release\v-simple-editor.exe --selftest=export-meta G5 / G6 が SKIP)。
      (c) 環境依存で SKIP になり得るゲート: export-alpha G5 (libvpx-vp9 のエンコーダまたはアルファデコーダ無し) /
          export-presets G5 (AV1 エンコーダ無し) / export-meta G5・G6 (libvpx-vp9 無し。4 PASS + 2 SKIP になる) /
          feature-tracker G6 (Debug ビルドで SKIP。Release では PASS) / audio-fixture (前提の
          test_assets/e2e_hum.wav か ffmpeg が無いと G1..G5 が全て SKIP)。ほかに legacy-kf G1 / G2 / G8 と
          special-composite G1..G4 (mpeg4 エンコーダ無し)、grade-keyframe G7 / G10 (OpenGL が使えない環境。
          10 PASS + 2 SKIP になる) も環境依存で SKIP になる。
      (d) タイムアウト: VEDITOR_SELFTEST_TIMEOUT_SEC (秒。既定 900、0 で無効) を超えると、stderr に
          `summary: TIMEOUT after <N>s (selftest=<名前>)` を出して終了コード 124 で打ち切られる。FAIL / SKIP
          とは別で、PASS 行は途中までしか出ていない。起動直後に `[watchdog] armed <N>s (<名前>)` または
          `[watchdog] disabled` が出る。--selftest=all は VEDITOR_ALL_SELFTEST_FILTER (カンマ区切りの順序つき
          リスト) で絞れ、未知または空の項目は終了コード 2 になる。
      (e) selftest の前に残ったプロセスを片付ける: `tasklist | findstr v-simple-editor` で残りを探し、
          `taskkill /F /IM v-simple-editor.exe`。前回の実行やエディタが残っていると、exe のロックや MCP ポート
          占有で selftest が失敗することがある。
      (f) VEDITOR_MCP_PORT: MCP サーバの待受ポートを指定する (未指定は 8765 から。使用中なら連番で最大 20 ポート
          試す)。複数の selftest やエディタを並行で動かすときは別のポートを指定する。全部使い切ると
          「MCP サーバを起動できませんでした: ポート A-B (...)」の警告が出る。
      (g) audio-fixture: リポジトリのルートで実行し (test_assets/e2e_hum.wav と ffmpeg が必要)、
          VEDITOR_AUDIO_FIXTURE_OUT=<出力フォルダ> を必ず指定する。WSL から .exe を起動するときは
          WSLENV=VEDITOR_AUDIO_FIXTURE_OUT/p を付けて、Linux パスを Windows 形式に変換させる:
            VEDITOR_AUDIO_FIXTURE_OUT=/tmp/fx_new WSLENV=VEDITOR_AUDIO_FIXTURE_OUT/p ./build/Release/v-simple-editor.exe --selftest=audio-fixture
          a.wav / b.wav / c.wav / d.wav (素 / トラックゲイン半分 / フラット EQ / EQ + ゲイン半分) と
          audio_fixture.json が出力される。旧 exe と新 exe で別フォルダに出力して cmp (または fc /b) で
          比較すると、音声書き出し経路の回帰を byte 単位で確認できる。

  ※ 利用者向けの制限事項:
     ・FCPXML 読み込み (Wave 8 の US-710 で拡張、Wave 9 の US-807 / US-808 で gap の子 / J カット / 素材長を追加。詳細は 3.10 (12)、3.10b (6)(7)): 映像・音声とも最大 2 lane
       (トラック) まで。lane 0 を必ず採用し、残りは lane 番号の絶対値が小さい順に採用して、超えた lane は警告に出して
       読み飛ばす。アンカーの子要素として書かれた接続クリップは取り込み、音声専用の asset-clip は音声トラックに置く。
       transition / clip 要素 (複合クリップ) / ref-clip / マルチカム (mc-clip) は今も読み飛ばして警告に積む。
       Wave 9 から、gap の子の接続クリップと、親より前に始まる接続クリップ (J カット) も取り込む。0 秒より前に全体が出るクリップ (切り詰めると長さが 0) は取り込まれず、「クリップの値が不正です (接続位置): <名前> / <ref>」で読み飛ばされる。0 秒より前に一部だけ出るクリップは切り詰めて警告「接続クリップをタイムライン 0 で切り詰めました: <名前> / <ref>」。接続クリップを持つ親クリップの時刻範囲が不正 (duration が 0、または offset / start の計算が不正) な場合、その親は「lane N の時刻範囲が不正なクリップを読み飛ばしました: <名前> / <ref>」で、その接続クリップは「親クリップが不正なため接続クリップを読み飛ばしました: <名前> / <ref>」で、警告付きで読み飛ばし、子を持たない gap は警告を出さない。
       (Wave 7 時点では接続クリップを読み飛ばし、音声専用 asset-clip も映像トラック側に置いていた。)
     ・速度ランプまたはタイムリマップを設定したクリップには、カメラ解析の結果を適用できない (ダイアログに
       理由が出る)。回避するには、ランプを外した状態で解析してからネストするなどの方法を取る (項目 (22))。
     ・特徴点追跡の範囲 (開始/終了フレーム) は素材先頭を 0 としたフレーム番号で指定する (ダイアログを開くと
       クリップのトリム (inPoint/outPoint) に合わせて既定値が自動入力され、最大 60 フレームの窓にクランプ
       される)。適用結果自体もクリップの inPoint・速度・逆再生を反映してタイムライン上の時刻へ変換される
       ため、トリム・速度変更・逆再生は正しく反映される (項目 (22))。
     ・(Wave 9 で変更) バッチ書き出しキューの音声は、現在のプロジェクトのタスクでは自動ラウドネス無しでもタイムラインのミックスになる (3.10b (1))。

       RenderInPlace / レンダーキューダイアログの手動追加では効かない (項目 (21)、3.10 (13))。

            期待: FCPXML は (asset の start が 0 の場合) 右端を素材の終わり (10 秒) まで伸ばせる (asset に長さが無い FCPXML は従来どおり使用範囲まで。start が 0 でない asset は右端を伸ばせる範囲が start ぶん短くなることがある。制限事項を参照)。EDL は素材ファイルが
                  見つかり probe が正の値を返したイベントだけ素材長が入り、probe 値が使用範囲の終わりより長いときだけ右端を素材の終わりまで伸ばせる (それ以外は従来値)。

                  ハンドルとして確保され常に正になるため (0 フレームのディゾルブはハンドルが 0 になり得て、trail は正にならない)、トランジション区間の描画が変わる。送り側クリップは、そのハンドル分だけは常に右端を伸ばせる。
                  (2) ハンドルを超えて素材長まで伸びるのは、素材が見つかり probe が正の値を返し、その値がハンドル込みの長さより長いときだけ。
            制限: EDL はソースのスタートタイムコードを差し引かない (既存の制限)。
     LLM:   「この FCPXML / EDL を取り込んで」→ import_fcpxml / import_edl (引数・応答は不変)。取り込み後の右端の延長は GUI のトリム操作。
     Undo:  取り込みで作られたシーケンスは Ctrl+Z (従来どおり)。右端のトリムは操作ごとに Ctrl+Z 1 回
     selftest: --selftest=fcpxml-import (17 ゲート) / --selftest=edl-import (13 ゲート。GateTally に移行。Wave 7 時点は 4)
