■ 3.1 共通の検証ルール
  ・LLM への指示は「〜して」と自然文で OK。LLM が MCP ツールを選んで実行します。
  ・各操作後に次の 3 点を確認:
      (a) タイムライン/プレビューが指示どおり変わった
      (b) Ctrl+Z 1 回で元に戻る (Undo あり のツール)
      (c) get_timeline / get_project_info の応答に新しい値が反映されている
  ・まず「今のタイムラインを教えて」と聞いて get_timeline の出力を見るのが確実です。
  ・ツール ID (list_commands の file.11 等) は位置依存なので、run_command を使う指示は
    「先に list_commands で確認してから」と付けると安全です。
  ・危険なコマンド: 終了系は MCP から実行不可。モーダルダイアログ系は allowBlocking が必要。

  ▼ (3) トラックフラグの保存

            「今のタイムライン」で label:"red" / "blue"

  ▼ (5) 逆再生

■ 3.9 Wave 7 新機能の検証チェックリスト

  ※ Wave 7 で MCP に増えたのは set_clip_enabled / group_clips / ungroup_clips / import_edl / import_fcpxml の
     5 ツール (47 → 52)。export_video に metadata (title/author/copyright/comment) が増え、keepAlpha は
     ProRes 4444 / 4444 XQ に加えて VP9 でも受理するようになった (既存フィールドと required は不変)。
     連番静止画書き出し・字幕の mov_text 埋め込み・自動ラウドネス正規化は書き出しダイアログのみの機能で、
     export_video の引数には含まれない。
     mcp selftest は G171..G177 が追加 (G1..G177)。
  ※ 4 件は既存挙動が変わる:
     (US-601) ラウドネス正規化のゲイン / ノーマライザ量がプロジェクトに保存されるようになる。従来は保存されず、
         開き直すたびに既定へ戻っていた。
     (US-604) メディアプールの「未使用素材を削除…」および既存の「未使用」フィルタ (両方とも同じ
         usedPaths プロバイダを共有) の判定対象が LUT・画像オーバーレイ・パーティクル設定の参照まで
         広がる。従来はメディアプールの既存プロバイダの参照だけを見ていた。
     (US-619) トラックに FX を一切掛けていないクリップでも、ミキサーのフェーダー / ノーマライズで設定した
         トラックゲインが書き出し音声に反映されるようになる。従来は再生では音量が変わるのに書き出しでは
         元の音量に戻る不整合があった。
     (US-620) 書き出し後のラウドネス後処理が出力ファイルを正しく置換できるようになり、(US-601) で保存される
         ようになった手動ラウドネスゲインが実際に書き出しへ適用されるようになる。従来は Windows で
         出力ファイルの置換に失敗することがあった。
  ※ 利用者向けの制限事項:
     ・FCPXML 読み込みは spine 直下の asset-clip を最大 2 lane まで取り込む。lane 番号の小さい順に採用する
       ため、負の lane が 3 種以上ある場合は本編 (lane 0) が読み飛ばされ警告に出る。アンカーの子要素として
       書かれた接続クリップ (Final Cut Pro の標準出力形式)、transition / clip 要素 (複合クリップ) /
       ref-clip / マルチカム (mc-clip) は読み飛ばして警告に積む。音声専用トラックの復元には対応しておらず、
       hasVideo を判定しないため音声専用の asset-clip も映像トラック側に配置される (項目 (18))。
     ・速度ランプまたはタイムリマップを設定したクリップには、カメラ解析の結果を適用できない (ダイアログに
       理由が出る)。回避するには、ランプを外した状態で解析してからネストするなどの方法を取る (項目 (22))。
     ・特徴点追跡の範囲 (開始/終了フレーム) は素材先頭を 0 としたフレーム番号で指定する (ダイアログを開くと
       クリップのトリム (inPoint/outPoint) に合わせて既定値が自動入力され、最大 60 フレームの窓にクランプ
       される)。適用結果自体もクリップの inPoint・速度・逆再生を反映してタイムライン上の時刻へ変換される
       ため、トリム・速度変更・逆再生は正しく反映される (項目 (22))。
     ・バッチ書き出しキューでは自動ラウドネス正規化が効かない。書き出しダイアログからの通常書き出しと、
       モバイル書き出しのバッチ経路でのみ有効 (項目 (21))。
     ・ミキサーでノーマライズ (またはフェーダー) を適用したプロジェクトは、トラックに FX を掛けていない
       場合でも書き出し音声にそのゲインが反映されるようになった。これまでは再生では音量が変わるのに
       書き出しでは元の音量に戻る不整合があった (この節冒頭「4 件は既存挙動が変わる」の US-619 と同じ事象、
       項目 (20))。
